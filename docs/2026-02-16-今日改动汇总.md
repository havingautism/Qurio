# 2026-02-16 今日改动汇总

本文用于同步今天围绕「专家模式渲染、HITL 表单续跑、流式思考/工具调用显示」的主要改动，便于团队交接。

## 一、改动目标

- 专家模式尽量复用普通会话渲染能力（思考过程、工具调用、正文流式）
- 修复专家模式的重复渲染、异常换行、思考/工具不显示问题
- 修复 HITL（交互式表单）第二轮续跑不稳定与 run_id 相关报错
- 降低 provider（尤其 NVIDIA/GLM）在 reasoning/tool stream 下的兼容差异

---

## 二、前端改动（重点）

### 1) 专家模式渲染结构调整

- 将专家消息展示收敛到 `MessageBubble` 主渲染路径，减少专家模式与普通会话分叉。
- `ExpertMessageBubble` 仅负责传入 `messageOverride`（当前激活 agent 视图），不再额外堆叠重复 UI。

涉及文件：
- `src/components/expert/ExpertMessageBubble.jsx`
- `src/hooks/expert/useExpertAgentSelection.js`
- `src/lib/chat/expertViewAdapter.js`

---

### 2) 修复「专家子问题重复显示」

- 去除外层重复注入的任务卡片，避免同一 agent 子问题显示两次。
- 保留 `MessageBubble` 内部统一的任务展示入口。

涉及文件：
- `src/components/expert/ExpertMessageBubble.jsx`

---

### 3) 修复专家模式思考/工具调用显示异常

- 专家消息渲染时，禁用 `streamBlocks` 优先回放（专家场景易导致“流式有、结束后丢失/错位”），改回使用 `thoughtHistory + toolCallHistory` 组装。
- 增加流式文本块合并，避免专家模式流式时“每个 chunk 一行”。

涉及文件：
- `src/components/MessageBubble.jsx`

---

### 4) 专家模式默认开启思考

- 专家模式下强制 `thinking = true`，避免因开关状态导致无思考输出。

涉及文件：
- `src/lib/chatStore.js`

---

### 5) 专家模式 stream 解析向普通会话对齐

- 补充 reasoning 解析兼容：
  - `reasoning_content`
  - `delta.reasoning_content`
  - `choices[0].delta.reasoning_content`
- 补充工具事件兼容：
  - `tool_call` / `tool_call_started`
  - `tool_result` / `tool_call_completed`
- 对流内容做协议噪声清理（`<think>`、`<|tool_call...|>`、`<|tool_calls_section...|>`）。
- `onFinish` 阶段兼容 `toolCalls` 与 `tool_calls` 两种字段。

涉及文件：
- `src/lib/chatStore.js`

---

### 6) 专家模式工具能力透传补齐（与普通会话一致）

- 专家子 agent 调用后端时新增透传：
  - `toolIds`
  - `userTools`
  - `enableLongTermMemory`
  - `databaseProvider`
  - `contextTurns`
  - `searchProvider / tavilyApiKey / serpapiApiKey`
  - `memoryProvider / memoryModel / memoryApiKey / memoryBaseUrl`

目的：避免“普通会话有工具、专家模式无工具”的能力差异。

涉及文件：
- `src/lib/chatStore.js`

---

### 7) 专家计划失败处理策略调整

- 以前：专家计划失败后可能继续执行或回退普通会话
- 现在：专家计划失败即暂停当前专家流程，不继续执行子 agent，并在专家计划区显示错误状态

涉及文件：
- `src/lib/chatStore.js`

---

## 六、给同事的快速结论

- 今天的主线不是“加新功能”，而是把专家模式拉回普通会话的稳定渲染链路。
- 核心原则：**专家模式只多一层计划与 agent 调度，不应有独立且弱化的消息解析逻辑**。
- 如果后续再出现显示不一致，优先检查 `chatStore` 专家分支是否又偏离普通会话 `callAIAPI` 的事件处理方式。
